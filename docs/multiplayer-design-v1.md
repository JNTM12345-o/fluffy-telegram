# 多人抢答游戏 · 设计方案 v1.0

## 1. 核心玩法

### 1.1 连接方式
- **局域网房间模式**：房主（主机）创建房间，生成 4 位房间码；其他玩家在同一 WiFi 下输入房间码加入
- **人数**：3-6 名玩家同时对战
- **主屏展示**：题目、倒计时、大屏分数板显示在主机（大屏设备）上；各玩家用手机抢答

### 1.2 游戏流程
1. **创建房间**：房主设置「每题时间」+ 「答错扣分」，生成 4 位房间码
2. **玩家加入**：其他玩家输入房间码，给自己起昵称（最多 6 字符），加入房间
3. **等待开始**：所有人准备就绪后，房主点击「开始游戏」
4. **抢答轮次**：每轮题目展示 → 所有人手机显示「抢答」按钮 → 第一个按下者获得答题权 → 在主机上作答 → 反馈对错 → 进入下一题
5. **结果展示**：10 题结束后，所有人看到排名和各自得分

### 1.3 计分规则
- **答对**：+100 分 + 剩余时间奖励（每快 1 秒 +10 分）
- **答错**：扣除房主设定的分值（0 / 50 / 100），本题结束
- **超时**：视为答错，扣除设定分值，其他人可继续抢答本题
- **无人抢答**：跳过本题，进入下一题
- **首个抢答者未作答而断开**：本题作废，其他人可抢答

## 4. WebSocket 消息协议

### 4.1 消息类型定义

```typescript
// 玩家状态
interface Player {
  id: string           // 随机 UUID
  nickname: string      // 昵称
  score: number         // 当前得分
  isHost: boolean       // 是否房主
  isReady: boolean      // 是否准备就绪
  isConnected: boolean  // 在线状态
}

// 房间状态
interface RoomState {
  roomCode: string      // 4 位大写字母数字
  players: Player[]
  phase: 'waiting' | 'playing' | 'result'
  currentQuestion: number  // 当前题目索引（-1 表示等待）
  config: RoomConfig
}

// 房间配置
interface RoomConfig {
  timePerQuestion: 5 | 10 | 15
  wrongAnswerPenalty: 0 | 50 | 100
  totalRounds: 10
}
```

### 4.2 消息流

| 方向 | 消息名 | 载荷 | 说明 |
|------|--------|------|------|
| C→S | `create_room` | `{nickname, config}` | 创建房间 |
| C→S | `join_room` | `{roomCode, nickname}` | 加入房间 |
| C→S | `toggle_ready` | `{}` | 切换准备状态 |
| C→S | `start_game` | `{}` | 房主开始游戏 |
| C→S | `race_answer` | `{}` | 玩家抢答 |
| C→S | `submit_answer` | `{selectedIndex}` | 提交答案 |
| S→C | `room_state` | `RoomState` | 房间状态同步（全量） |
| S→C | `game_event` | `{type, data}` | 游戏事件通知 |
| S→C | `question_data` | `{question, round}` | 题目数据 |
| S→C | `round_result` | `{correct, correctIndex, scores}` | 本轮结果 |

### 4.3 核心游戏状态机

```
waiting → playing → result
  ↑_________|          |
  (重开)   (10题结束)  (返回waiting)
```

## 5. 组件设计

### 5.1 LobbyPage（主页）
- 两个入口：**「创建房间」** 和 **「输入房间码加入」**
- 创建房间：输入昵称 → 配置难度 → 生成房间码 → 进入 HostPage
- 加入房间：输入房间码 + 昵称 → 连接成功 → 进入 PlayerPage

### 5.2 HostPage（主机大屏）
- **顶部**：房间码（醒目显示）+ 在线玩家列表
- **中央**：题目卡片 / 等待界面 / 结果界面（根据 phase 切换）
- **右侧**：实时分数板（所有玩家分数滚动更新）
- **底部**：计时条 + 当前题目进度
- **答题权提示**：显示当前抢到答题权的人昵称

### 5.3 PlayerPage（手机端）
- **等待阶段**：房间信息 + 在线玩家 + 「已准备」按钮
- **抢答阶段**：大号「⚡ 抢答」按钮（圆圈脉冲动画，60% 屏幕高度）
- **作答阶段**：4 个选项按钮（滑动或点击选择）
- **反馈阶段**：显示对/错，等待下一题

### 5.4 ScoreBoard（多人分数板）
- 展示所有玩家昵称 + 实时分数
- 当前答题者高亮
- 分数变化时动画数字跳动
- 排名顺序实时排列

### 5.5 RoomLobby（等待大厅）
- 显示所有已加入的玩家
- 每个玩家显示昵称 + 准备状态
- 房主看到「X/3 人已准备，开始按钮」提示
- 非房主看到等待提示

## 6. 计分细节

### 6.1 分数计算
```
基础分 = 100
时间奖励 = floor(剩余秒数 × 10)
本题得分 = 基础分 + 时间奖励（仅答对时）
本题扣分 = 房主设定值（答错/超时时）
```

### 6.2 边界情况
- **分数可低于 0**（激烈对战可能出现负分）
- **首个抢答者断开连接**：本题作废，其他人重新抢答
- **所有人离线**：房间保留 5 分钟，可重新连接
- **房主离开**：房间解散，其他人被踢回主页

## 7. UI 设计方向

- **风格**：保持现有赛博朋克风格，统一视觉语言
- **主机大屏**：更大字体，更醒目的倒计时条，选手分区清晰
- **手机端**：极简设计，超大触摸按钮，抢答按钮占屏幕 60%
- **颜色区分**：每个玩家分配一个固定霓虹色（青/粉/紫/绿/黄/橙）
- **动画**：抢答成功时玩家色块闪烁，答题正确分数飞入动画
